# HVWA (Holy Vulnerable Web App) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a modern, self-hostable successor to DVWA with 100+ discrete, flag-bearing security challenges spanning classic web, modern API, AI/LLM/agentic, supply chain, and blue-team domains, each playable at four difficulty levels with a built-in scoreboard and side-by-side vulnerable/secure code view.

**Architecture:** One Node.js + TypeScript server (Express 5) hosts a *portal* and nine *districts*, each district a mounted router of intentionally vulnerable surfaces rendered with EJS. A **declarative challenge registry** (one TypeScript module per challenge) drives metadata, difficulty routing, hint tiers, flag issuance, and automated solve-checking — this registry is the mechanism that makes "100+ challenges" cheap to reach and maintain. State lives in `node:sqlite` (native, no native-module build). Dangerous primitives (RCE, SSRF, deserialization) run only inside a locked-down Docker container.

**Tech Stack:** Node 22 LTS, TypeScript 5, Express 5, EJS, `node:sqlite`, Zod, Vitest + Supertest, plain CSS + vendored htmx for UI (fully offline, no CDN), Nunjucks (only inside the SSTI challenge), Docker + Compose for isolation.

**Non-negotiable safety rule:** HVWA is deliberately vulnerable. It binds to `127.0.0.1` by default, ships egress-blocked, and runs RCE-class challenges only in the hardened container (Task group P0-SEC). Never expose it to a hostile network.

## How we reach 100+ challenges

A **challenge** is one discrete, flag-bearing task. A **district** groups related challenges. A **difficulty level** (Acolyte → Templar → Inquisitor → Divine) is a property *within* a challenge, not a separate challenge.

The full catalog below enumerates **122 challenges** across 9 districts (≈15% margin over the 100 target). Each is defined once as a registry entry; the engine renders it, issues its per-instance flag, serves tiered hints, and verifies solves. Adding a challenge = adding one registry module + its router handler + one spec test. This is why the count scales.

Difficulty theme (replaces DVWA's Low/Medium/High/Impossible):

| Level | DVWA equivalent | Meaning |
|---|---|---|
| **Acolyte** | Low | No protection |
| **Templar** | Medium | Naive/blacklist filter |
| **Inquisitor** | High | Real but flawed defense |
| **Divine** | Impossible | Correct, ASVS-aligned reference implementation (the "view the fix" target) |

## Core engine contracts (defined once, used everywhere)

These types are referenced by every later task. Defined in full in Task 3.

```typescript
// src/core/registry.ts
export type Level = 'acolyte' | 'templar' | 'inquisitor' | 'divine';

export interface HintTier { id: 1 | 2 | 3; text: { id: string; en: string }; cost: number; }

export interface Challenge {
  id: string;                 // e.g. "GK-01"
  district: string;           // e.g. "gatekeeper"
  slug: string;               // url segment, e.g. "sqli-login"
  title: { id: string; en: string };
  summary: { id: string; en: string };
  maps: string[];             // ["A05:2025","CWE-89"]
  levels: Level[];            // which levels are implemented
  points: number;             // base points (scaled by top level solved)
  hints: HintTier[];
  // verify a submitted solution for a given session+level; return true on solve
  check: (ctx: CheckContext) => Promise<boolean> | boolean;
  mount: (router: import('express').Router) => void; // attaches vulnerable routes
}

export interface CheckContext {
  sessionId: string;
  level: Level;
  submission: string;         // flag or answer the player submits
  db: import('node:sqlite').DatabaseSync;
}
```

The **flag** mechanism (Task 4): most challenges succeed by exfiltrating a per-instance canary. `issueFlag(challengeId, sessionId, level)` = `HMAC_SHA256(flagSecret, challengeId|sessionId|level)` truncated and prefixed `HVWA{...}` — **one distinct flag per exploitable level** (Divine never issues a flag). The vulnerable surface exposes this canary only when genuinely exploited. `POST /api/submit` takes only `{ challengeId, submission }`: the server tries `check()` for each implemented non-Divine level, highest first, and records the solve at the first level that matches. The client never supplies the level, so points cannot be inflated. Default `check` = `verifyFlag(id, ctx.sessionId, ctx.level, ctx.submission)`. Score = sum over challenges of the best level's points (`base × {acolyte 1, templar 1.5, inquisitor 2}`) minus unlocked hint costs, floored at 0. Puzzle-type challenges (WT-02/03) override `check()` with custom logic.

```typescript
// src/db/index.ts
import { DatabaseSync } from 'node:sqlite';
import { readFileSync } from 'node:fs';
import { fileURLToPath } from 'node:url';
import { dirname, join } from 'node:path';
const here = dirname(fileURLToPath(import.meta.url));
export function openDb(path = 'hvwa.db'): DatabaseSync { return new DatabaseSync(path); }
export function migrate(db: DatabaseSync): void {
  db.exec(readFileSync(join(here, 'schema.sql'), 'utf8'));
}
```

import { createHmac, timingSafeEqual } from 'node:crypto';
import { config } from '../config.js';
export function issueFlag(challengeId: string, sessionId: string): string {
  const mac = createHmac('sha256', config.FLAG_SECRET)
    .update(`${challengeId}|${sessionId}`).digest('hex').slice(0, 32);
  return `HVWA{${mac}}`;
}
export function verifyFlag(challengeId: string, sessionId: string, submission: string): boolean {
  const expected = Buffer.from(issueFlag(challengeId, sessionId));
  const got = Buffer.from((submission ?? '').trim());
  return expected.length === got.length && timingSafeEqual(expected, got);
}

// src/core/session.ts
import { randomUUID } from 'node:crypto';
import type { RequestHandler } from 'express';
export function sessionMiddleware(): RequestHandler {
  return (req, res, next) => {
    let sid = req.cookies?.hvwa_sid as string | undefined;
    if (!sid) {
      sid = randomUUID();
      res.cookie('hvwa_sid', sid, { httpOnly: true, sameSite: 'lax', path: '/' });
    }
    (req as any).sessionId = sid;
